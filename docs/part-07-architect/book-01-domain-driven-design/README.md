# 《领域驱动设计 DDD》

> Part VII · 第 1/3 本 · 状态 🟡（目录已立）

## 定位

业务复杂到代码撑不住时，DDD 提供一套「让模型对齐业务」的战术与战略工具。本卷教你在**恰当的复杂度**下用 DDD，而不是到处贴聚合与事件。

## 前置

[《设计模式与重构》](../../part-03-single-app-engineering/book-02-patterns-refactoring/README.md)、Part III–VI（见过真实复杂业务）。

## 收官实验

选一个中型业务（订单/内容系统），先做事件风暴建模产出限界上下文图，再按战术设计落地一个聚合示例并写建模复盘。

## 武器自限

收官重在「建模过程 + 边界划分」的记录，不以代码量为考核。
