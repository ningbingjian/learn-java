# 写作规范（writing-guide）

本文件是整套课程的「宪法」：它定义了每章长什么样、写到多深才算写完、用什么语气、代码怎么处理。
写任何一章之前，先读这里。

## 1. 这本书是谁、给谁

- **自用，但按可出版标准组织。** 不写给自己看不懂的速记，也不写给陌生读者的营销话术。语气：清晰、可复核、可复查。
- **作者即读者**：你写到某一层时，那层就是你当时真实掌握的深度。没掌握的层，写「问题 + 阅读地图 + `[待证]`」，不硬写。

## 2. 两层「从零到资深」

| 层 | 含义 |
|---|---|
| 全书 | Part I（零基础语法）→ Part VII（架构师）。只能按部序推进；部内按书序。 |
| 每书 | 书是「可独立成书」的主题，书内部从这门主题的零基础讲到它的资深。 |
| 每章 | 章节内部也按**四层海拔**推进，见下节。书/部越靠后，「资深」绝对水位越高。 |

## 3. 四层海拔（每章内容都要能落到这张表）

写任何一个主题，先自问内容分别属于哪一层；**写到 L4 才算把这一章写穿**：

| 层 | 问题 | 判定（做得到才写） |
|---|---|---|
| **L1 会用** | 这是什么、怎么调？ | 能写出可跑的示例 |
| **L2 原理** | 内部怎么跑、为什么这样？ | 能讲清机制，不靠「听说的」 |
| **L3 取舍** | 什么时候**不能**用它？反模式/失败现场？ | 能主动给出反例与失败场景 |
| **L4 落地** | 生产怎么衡量、怎么演进？ | 有数字（压测/指标/基准）支撑结论 |

**写不过 L4 的层怎么办**：那一层暂时只写「问题清单 + 延伸阅读地图 + `[待证]`/`[深潜]` 标记」。宁缺毋错——错误的结论会变成你自己的错误记忆。

## 4. 章节模板与文件命名

- 粒度：**部（Part）→ 书（Book）→ 章（Chapter）**。一本书的定位/目录/自限/收官实验写在它的 `README.md`；正文一章一个文件。
- 正文文件一律 `docs/part-0X-*/book-NN-<书slug>/chNN-短横线小写标题.md`；`NN`=该书在部内的阅读序号（见 CURRICULUM），章号**每本书内各自从 01 起**连续编号。
- 结构照抄 [docs/_chapter-template.md](../_chapter-template.md)，不要自创章节结构。
- 新章写完：登记进该书 `README.md` 的章目录，并到根 [CURRICULUM.md](../../CURRICULUM.md) 更新状态。

## 5. 代码与「真实可跑」规则（硬规则）

1. **正文引用的代码必须是 `demos/` 下的真实文件路径**，用相对链接指过去；允许贴关键几行，但必须同时给到完整可跑位置。禁止「看起来对但没编译过」的伪代码冒充示例。
2. **每个 demo 独立成 Maven 工程**，从仓库根可 `cd` 进去一键跑（见各自 README）。正文默认环境 = JDK 21 + `./mvnw`。
3. **用 `maven.compiler.release` 锁语言版本**：正文讲 21 特性时，示例工程里就开 21；没讲到的特性别偷偷用高版本语法，否则读者照抄编译不过。
4. **自测即自检引擎**：能用断言/测试验证的知识点，写成 JUnit 测试当「自测题」的判分器。一个实验的「预期输出/验收标准」必须写清楚，读者才知道自己对了没。
5. 图示用 **Mermaid**（纯文本、可 diff），不贴截图。真需要贴输出/截图时，注明生成它的命令与日期。

## 6. 标记约定（正文里的「活体组织」）

| 标记 | 含义 |
|---|---|
| `[待证]` | 没把握、待验证的结论（写下来是为了追，不是免责） |
| `[深潜]` | 该话题属于后续卷/章，这里只点到；留索引 |
| `[TODO-实验]` | 需要跑一个实验补数字，暂缺 |
| `[?]` | 一个还没答案的好问题——保留它比假装有答案重要 |

## 7. 写作收尾自检（每章提交前过一遍）

- [ ] 内容已标到 L1–L4 哪几层？没到 L4 的层是否有明确标记？
- [ ] 每段正文引用的代码都真实存在且能跑？（跑一遍 `./mvnw test`）
- [ ] 自测题有「判分器」或「答案页」？
- [ ] 章节文件已登记进对应卷的 `README.md` 卷地图？
- [ ] `todo.md` 里对应状态已更新？

## 8. 修订记录

每次对「结构/规范」的改动，在 `docs/meta/changelog.md` 记一行；正文内容改动不必记。
