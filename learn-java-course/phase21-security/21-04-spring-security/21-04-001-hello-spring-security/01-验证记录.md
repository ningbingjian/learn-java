## 本次验证范围

验证日期：2026-09-07。环境：macOS arm64、OpenJDK 21.0.9、Maven 3.9.9、Spring Boot 4.0.8、Spring Security 7.0.7、Spring Framework 7.0.9。实际依赖树另确认 Tomcat 11.0.24 与 JUnit Jupiter 6.0.3。

验证同时覆盖仓库完成版和正文的中间状态。跟写工程从正文的 XML、Java、properties 代码块生成，使用同一模块父 POM；先构建没有安全依赖的初始版本，再只加入正文指定的安全依赖，最后加入预置测试。最终 Java、资源文件逐字与仓库完成版一致，POM按XML结构核对一致。

## 完成版与跟写最终状态的自动化测试

在模块目录执行 `mvn clean verify`，聚合父工程与第一课均构建成功。随后在跟写单课目录执行同一命令，也构建成功。两次均为：

```text
Tests run: 7, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

上面是实际运行的稳定摘要，不包含完整启动日志或执行耗时。报告位于对应单课的 `target/surefire-reports/`，不把生成目录提交到仓库。

| 用例 | 实际验证 |
| --- | --- |
| JSON请求无凭据 | 401、Basic认证挑战、没有业务JSON |
| HTML请求无凭据 | 302，Location路径为/login |
| 默认登录页 | 200，含用户名、密码和CSRF隐藏字段 |
| 错误密码 | 401，没有业务JSON |
| 正确密码 | 200、JSON响应类型及精确业务内容 |
| 成功后的独立匿名请求 | 前次200，后次仍401 |
| 不存在路径 | 匿名401，正确认证后404 |

测试通过完整嵌入式服务器和JDK HTTP客户端进行，不模拟已认证用户。测试上下文的固定密码用于可重复请求，不替代下面的随机默认密码验证。

## 逐步跟写与普通启动

从正文构建的无安全依赖版本、加入安全依赖版本都单独执行了 `mvn clean verify`，并启动生成的可执行包发送真实HTTP请求。普通启动保持随机默认密码，验证过程没有写入生产用户配置。

| 观察点 | 实际结果 |
| --- | --- |
| 初始匿名/hello | 200、业务JSON，方法标记出现一次 |
| 初始运行日志 | 没有生成安全密码的日志 |
| 加入依赖后匿名JSON请求 | 401及Basic挑战，方法标记未出现 |
| 仅修改Accept为text/html | 302到/login |
| 单独请求/login | 200及登录表单字段 |
| 错误密码 | 401，仍未执行问候方法 |
| 修复为当前进程生成密码 | 200及业务JSON，方法标记出现一次 |
| 独立无凭据再次请求 | 401，方法标记计数不增加 |
| /missing匿名与认证请求 | 分别401、404 |
| 回到正确凭据的/hello | 恢复200与业务方法执行 |
| 重新启动 | 生成新密码，旧密码401、新密码200 |

以上连同最终测试和文件一致性检查，共18项跟写检查通过。方法执行证据来自本课固定日志标记与请求前后的计数对照，不把响应体断言当作内部执行证明。

另外核对正文的 `mvn spring-boot:run` 启动方式：初始版本匿名请求200，加入依赖版本匿名请求401。测试时使用 `--server.port=0` 分配空闲端口，客户端读取实际端口后发送请求；除端口外保持课程配置。可执行包与Maven启动都在验证结束后正常停止。

## 复现与边界

读者可以按正文第1—4节重新跟写，用响应头与方法日志逐项核对上表；再执行第5节的测试。聚合构建、单课运行和依赖核对命令分别见[模块入口](../README.md)与[版本基线](../01-版本基线.md)。

本次验证了默认登录页的HTTP响应与表单字段，没有执行浏览器GUI操作、人工IDE断点操作、浏览器表单登录后的会话恢复、角色授权或生产性能测试。正文提供的IDE断点是可选观察方法；业务执行结论已经用实际日志验证。POST/CSRF、登录会话和403权限不足属于后续课程范围，不把当前7项测试描述为整个框架的完整安全验证。

通用规范自查已覆盖：每个核心小节的理论与操作因果关系、修改位置及执行目录、错误凭据修复闭环、小总结和整课总结、前后知识衔接、代码与文档一致性。导航检查只针对本次新增内容及总导航新增链接，未重写或重跑无关IoC课程。
