## 5项浏览器测试的证据

1. **无安全依赖的后端**：页面点击后得到HTTP200与真实业务JSON，后端 `HELLO_HANDLER_REACHED` 计数增加一次。
2. **启用安全依赖的后端**：页面得到HTTP401，代理保留 `WWW-Authenticate: Basic...`；浏览器请求Accept为JSON，不携带Authorization或测试预置Cookie，后端业务日志计数保持零。
3. **后端实际停止与恢复**：停止Java进程后，同一页面得到开发代理生成的502与专用错误标记；在相同端口重启后端，再次点击恢复401。502不显示为“未通过认证”。
4. **浏览器离线与恢复**：页面加载后切换浏览器上下文为离线，请求显示“未取得完整响应”；恢复网络后，同一页面可重试并得到401。
5. **窄屏和键盘**：390像素视口无横向溢出，按钮通过键盘Enter激活，仍取得真实401。

每项浏览器测试采用隔离上下文；Java和前端服务使用空闲端口。前端与后端的版本对照由相同源码仅增减安全依赖实现，不通过放行全部请求伪造“未引入Security”的行为。测试过程中不输出密码或完整身份凭据。

截图与失败追踪保存在 `frontend/test-results/`，后端构建日志和脱敏后的方法计数保存在 `frontend/.e2e-work/`；这些生成目录不提交。实际观察到的401响应体为空，页面如实展示“（空响应体）”，没有制造JSON错误内容。

## 复现与边界

在完成版 `frontend/` 目录执行：

```bash
npm ci
npm run build
npx playwright install chromium
npm run test:e2e
```

Java21与Maven3.9.9必须可用；首次下载依赖和测试浏览器需要网络。安装匹配浏览器后，后续运行可省略安装命令。测试前的Java构建输出位于 `.e2e-work/secured-build.log`，浏览器终端摘要应为 `5 passed`。

本次验证了实际浏览器页面、同源开发代理、错误恢复及键盘/窄屏使用，没有验证浏览器直连后端的CORS策略、表单登录后的会话恢复、角色权限、生产部署、性能或其他浏览器。8秒超时和其他HTTP状态分支保留防御性处理，但本次未单独注入超时或每个状态码测试，不能从当前结果推断全部网络情况。第一课的IDE断点仍为可选观察方式，内部业务执行结论使用实际日志支持。
