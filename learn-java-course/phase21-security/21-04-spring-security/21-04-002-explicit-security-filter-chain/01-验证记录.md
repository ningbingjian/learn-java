## 后端与浏览器验证了什么

11项后端测试保留真实端口、实际凭据及不自动跳转的HTTP客户端，测试密码仅在测试上下文设置。覆盖公开JSON和安全响应头、查询字符串、四种近似/错误前缀路径、公开路径携带错误Basic、匿名JSON401、HTML302、默认登录页与CSRF字段、错误密码401、正确密码200、成功后独立匿名请求401，以及不存在路径匿名401/正确认证后404。

6项浏览器测试按以下范围取证：

1. 公开Controller已存在而自定义链尚未加入时，公开按钮仍返回401，公开业务方法未执行。
2. 正确显式链下，公开按钮返回200和真实JSON；浏览器没有携带预置Cookie或Authorization，后端公开方法日志增加一次，安全响应头仍存在。
3. 同页由公开按钮切换到受保护按钮，真实401及Basic认证挑战透传；本次路径和响应体更新，问候方法日志没有增加。
4. 实际停止后端时，两个按钮均取得代理502及专用错误标记；相同端口重启后分别恢复200、401。
5. 浏览器上下文离线时没有完整HTTP响应；恢复网络后两个按钮可重试并得到各自结果。
6. 390像素宽度下两个按钮均可用Enter激活，页面无横向溢出。

Java服务日志仅用固定业务标记计数，不把密码或完整身份信息放进页面、截图和摘要。401响应体本次实测为空，页面显示“（空响应体）”。测试使用随机端口、隔离浏览器上下文并在结束时关闭服务。

## 按正文重建与中间步骤验证

在仓库忽略的 `work/security-followalong/21-04-002-explicit-security-filter-chain`建立独立目录，直接执行正文的复制命令，逐字提取PublicInfoController、SecurityConfig及完整JavaScript代码块，再执行页面骨架和测试文件复制命令。并非直接复制第二课完成版后声称完成了跟写。

每次后端阶段变化都先构建再启动可执行包，使用当前进程生成的随机密码。21次HTTP检查覆盖下列步骤：

| 跟写阶段 | 实际结果 |
| --- | --- |
| 第一课源码改为第二课包名，尚无公开Controller | /hello匿名401、正确Basic200 |
| 新增公开Controller，尚无自定义链 | /public/info匿名401、正确Basic200；默认链配置匹配 |
| 加入正确显式链 | 公开200、保护401、正确Basic200、错误Basic401、HTML跳转及登录页可访问 |
| 核对规则边界 | 查询字符串200，近似路径和后端直接访问代理前缀均401 |
| 故意把规则改为 /api/public/info | 原公开请求匿名401，正确Basic仍200，保护接口仍401 |
| 在原位置改回 /public/info 并重启 | 公开200、保护401恢复 |

条件报告另核对：显式链存在时，`ServletWebSecurityAutoConfiguration.SecurityFilterChainConfiguration`不匹配，原因指向已有 `securityFilterChain` Bean；`UserDetailsServiceAutoConfiguration`仍匹配。正确随机密码可以访问受保护接口，与源码条件相互印证。运行记录脱敏保存，不提交整份含密码的启动日志。

最终逐文件比较跟写工程与正式工程的POM、Java、properties、前端配置、锁文件、HTML、CSS、JavaScript及测试脚本，内容一致。跟写目录内重新执行 `npm ci`、前端构建及完整联合测试，11项后端和6项浏览器测试通过。

## 复现、修正与范围

完成版在本课目录执行 `mvn clean verify`；在 `frontend/`执行 `npm ci`、`npm run build`、`npx playwright install chromium`和 `npm run test:e2e`。模块聚合验证从本课上一级目录执行 `mvn clean verify`。正确配置的日志及截图位于前端 `.e2e-work/`和 `test-results/`，这些生成目录不提交。

编写期间曾额外探查带Basic但缺少CSRF令牌的POST，最初预期403，实际最终响应为401；该假设不成立，没有把它写成本课契约。跟踪中先出现CSRF令牌拒绝和内部403处理，而最终HTTP为401，不能仅凭一个内部处理点断言最终响应；完整写请求/CSRF分析属于后续课程。本课保留默认CSRF配置，只以明确的GET条件和登录页字段说明当前范围，最终11项HTTP测试不包含那个不成立的POST断言。随后完整后端与浏览器验证均通过。
