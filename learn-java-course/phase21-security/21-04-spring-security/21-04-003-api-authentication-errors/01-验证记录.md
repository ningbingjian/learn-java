## 后端与浏览器证据

19项后端测试使用实际HTTP端口和真实凭据，不模拟登录用户。沿用公开/受保护与近似路径、正常/错误密码、登录页、独立匿名及缺失路由的对照；新增认证JSON的状态、字段、UTF-8说明、Basic挑战和不缓存要求，业务语言参数400/修复200，以及错误格式Basic、未知用户、HTML与混合媒体类型和后备Accept场景。

匿名、错误密码与未知用户的JSON认证失败均为401，错误体只含固定code/message，没有异常类、密码或账号是否存在的说明。HTML请求的302与实际可访问的登录页分别验证；登录页包含CSRF隐藏字段，本课没有关闭CSRF。

8项浏览器测试包括：

1. 只保留MVC处理器及参数校验、恢复第二课安全配置时，业务参数400具有JSON；匿名401仍没有本课认证契约，页面正确降级。
2. 完成版匿名请求取得真实401 JSON与Basic挑战，不携带预置Cookie或Authorization；认证入口日志增加，MVC及问候日志不增加；显式重试仍为401。
3. 非法lang返回真实400，并记录公开方法及MVC处理器日志，认证入口日志不增加；使用正常公开请求恢复200，旧错误代码清空、重试隐藏。
4. 浏览器实际导航到后端/hello，跳转/login并显示表单，而不是只断言一个302。
5. 实际停止后端得到代理502，重启后原路径重试恢复401 JSON。
6. 浏览器离线后未取得完整响应，恢复网络重试公开请求得到200。
7. 明确注入损坏JSON、HTML、状态与代码不符、未知代码、非字符串代码五组响应，仅验证前端保持原始状态/原文并降级；不用于证明后端认证正确。
8. 390像素视口下用Enter触发参数错误与重试，结果保持400且无横向溢出。

测试进程采用空闲端口，结束后关闭服务。运行日志仅以固定业务标记取证，不把密码、Cookie或完整认证头写进页面、截图和报告。前端构建日志、截图及失败追踪在 `.e2e-work/`和 `test-results/`，这些生成目录不提交。

## 编写期间的修正与验证边界

首次配置曾直接设置异常处理的全局认证入口，导致/login实际302而不是200。该测试正确发现默认登录页生成条件受影响；已改为按请求注册选择器，保留真实登录页测试，后端与浏览器完整回归通过。源码依据为Security7.0.7的DefaultLoginPageConfigurer，正文解释了该条件。

跟写探查也发现，简单恢复Basic默认配置并不保证最终响应失去JSON，不能以该预期教学。本课改用明确的“Basic失败回调只设置401”作为故障条件，并实际验证修复，不把默认机制与该错误回调混为一谈。

媒体匹配按本课明确顺序选择入口，不是完整q权重协商实现。尚未验证页面提交登录后的会话、角色权限、完整CSRF写流程、浏览器直连CORS、其他浏览器、生产部署或性能；其他业务异常不自动套用这两个错误代码。8秒超时仍是防御性处理，未逐一注入所有网络条件。
