## 后端证据与边界

`RequestBoundaryHttpTests`沿用第四课25项真实HTTP覆盖，并替换成member测试凭据：公开/保护、方法与近似路径、错误分派、CSRF拒绝、401JSON/HTML响应选择、默认登录页面/样式和带合法CSRF的登录提交均继续通过。新增三种账号分别正确200、错误401、未知路径403，以及旧默认user不可用两项测试，共27项。

`PasswordStorageTests`直接调用真实配置与编码器，5项覆盖：三用户存储带{bcrypt}、正确/错误匹配及ROLE_元数据；相同原始值不同盐但均匹配；丢失算法标识抛出异常、恢复完整记录匹配；错误地二次编码存储表示不能验证原始密码；空值、空白、短值、超过72个UTF-8字节的初始化输入拒绝。测试中{noop}仅为二次编码故障的隔离输入，不是正常用户存储。

普通启动没有内置实验密码；跟写实际以缺失环境变量启动，确认非零退出、出现输入约束提示且服务未完成启动。设置三个临时本机密码后启动成功，未再生成默认用户密码。测试密码只覆盖测试配置，未写入运行属性默认值。

源码依据为Security7.0.7的PasswordEncoderFactories、DelegatingPasswordEncoder、InitializeUserDetailsBeanManagerConfigurer、DaoAuthenticationProvider，以及Boot4.0.8的UserDetailsServiceAutoConfiguration，正文给出固定标签入口和适用条件。没有声称完成全部认证链源码调试。

## 浏览器证据

10项测试运行真实后端与Vite：

1. 默认用户对照版member认证401，显式用户版同一账号凭据200。
2. 匿名401契约、Basic挑战、不携带Cookie/Authorization，以及错误处理日志和匿名重试。
3. 参数400与公开正常200恢复、错误代码清理。
4. 实际后端页面导航进入可见默认登录表单。
5. 真正停止后端得到代理502，恢复后重试401。
6. 浏览器离线、恢复后重试公开200。
7. 专门注入5种异常格式，仅验证前端降级，不用来证明认证。
8. 390像素与Enter操作、无横向溢出。
9. 近似/未知路径401，OPTIONS与重试保持方法。
10. member/support/admin各自正确200，输入立即清空、结果区无密码或Basic值、localStorage与sessionStorage为空；错误密码401后无自动重试，下一次匿名按钮仍401。

身份输入通过表单submit接管为fetch，不把用户名密码放进URL；表单显式POST作为脚本未加载时的默认方法。本次在该属性完善后重新构建并运行完成版及跟写版各10项浏览器测试，通过。

网络追踪留存关闭，截图在密码框为空时生成；日志使用业务计数，不输出凭据。测试用空闲端口，结束关闭进程。未验证所有浏览器密码管理器，autocomplete只是提示；也不保证JavaScript内存擦除。
