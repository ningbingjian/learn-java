新增或调整的证据包括：默认表单302导致fetch结果不明但真实会话已建立；完成版POST使用表单编码、CSRF头与Cookie，无URL查询或Basic凭据；正确登录200后重新获取令牌；只带会话的GET200、共享新令牌探针200，而旧匿名按钮仍401；错误密码修复后点击或Enter登录成功；390px布局无横向溢出。

页面观察区和浏览器存储不含提交的测试密码与令牌；密码在请求构造后清空，截图记录清空后的桌面及窄屏状态，trace关闭。上述检查不承诺JavaScript内存安全擦除，也未测试所有浏览器密码管理器行为。

## 正文跟写与中间步骤

从仓库第六课复制到独立跟写目录，按正文逐步新增FormLoginHandlers、修改SecurityConfig，再按正文代码块新增三个前端模块与导入。实际执行正文的curl/Node请求及修复步骤，共18个HTTP状态检查：

- 默认响应阶段：取令牌200、表单登录302、Cookie访问200。
- JSON完成阶段：表单返回200/LOGIN_SUCCEEDED、后续会话200。
- 登录前令牌提交403；重新获取200、新令牌探针200、会话访问200。
- 缺令牌登录403；相同凭据错误JSON格式401/LOGIN_FAILED；已有会话仍200；恢复表单200，再获取令牌200。

跟写验证使用临时生成、含保留字符与中文的实验密码，通过环境变量供程序使用；没有录制交互式密码输入。请求命令按正文执行，仅将端口替换为隔离进程的随机端口。日志只保存状态与固定代码，临时密码、Cookie和令牌文件按正文清理。
