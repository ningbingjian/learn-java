## 教学主线与模块边界

主线采用独立前端项目与Servlet / Spring MVC后端：页面操作 → 浏览器请求证据 → 后端机制 → 匹配版本的源码。前端初期使用原生HTML、JavaScript和Vite，提供布局骨架，重点解释请求、凭据、身份状态与错误恢复。课程先建立Cookie/Session登录，再讨论外部身份、BFF和资源服务器；前后端分离不预设必须使用JWT。

同一个工单业务逐步演进：访客查看公开信息，用户管理自己的工单，客服处理分配给自己的工单，管理员维护用户与权限。隐藏菜单只改善界面，后端必须独立验证资源归属和操作权限。最终以真实页面、真实HTTP及可重置的实验数据共同证明结果。

后端为前端服务（BFF）负责保持浏览器会话并代为调用资源API；外部身份提供方（IdP）负责提供登录身份。二者在第六篇引入，本地Session登录阶段不要求先掌握它们。

21-01补充Web威胁，21-02补充密码学与TLS；OAuth 2.0/OIDC协议系统推导归21-03，授权服务实现归21-05，Keycloak平台治理归21-06，分布式会话存储归21-07。本模块负责应用侧使用、源码和整合。第一次引入外部服务时提供本地可重置夹具和足够的协议背景，不要求等待其他模块全部完成，也不在此重复建设完整授权服务器或身份平台课程。

## 每课工程、正文与验证约定

- 前置栏中的数字均指本模块课号，外部基础单独注明；“已完成”只有第001课，其余验收均是未来必须满足的目标。
- 每课保留完整 `frontend/` 和匹配后端；普通课程沿本篇说明的快照演进，源码与故障课复用稳定场景。正文写明复制来源、文件改动和运行入口，不能让学习者猜测继承关系。仅为实际编写的课程建立正式目录，并在交付时完成源码、验证及父POM接入，不预建空课。
- 核心小节遵循“理论 → 实操中解释原理 → 小总结”，课末有串联原理、结论、边界与应用方法的整课总结；本大纲的条目不能直接代替正文。完整要求以统一写作规范为准。
- 源码课必须提出问题，标记版本和类/方法入口，解释关键数据、条件、调用时机，并给出断点、日志或配置对照验证后再作结论。类名只是入口，不代表本次已完成运行追踪。
- 每课按目标保留成功和拒绝/故障验证；变更凭据交互时使用真实认证，涉及Cookie、CSRF、CORS时补浏览器证据。写接口授权测试时使用合法CSRF令牌隔离变量；网络故障与401/403分别呈现。
- 既有版本沿用[版本基线](01-版本基线.md)。H2、IdP、LDAP、原生工具链等尚未引入的依赖在首次开课时固定版本、提供初始化/重置和验证记录；不宣称本次已运行这些环境。秘密不进入前端源码、页面观察区或提交记录。

## 第二课的编写范围

第002课是本大纲之后的下一项交付，标题保持“显式定义公开接口与认证接口”。拟建目录为 `21-04-002-explicit-security-filter-chain/`，位于当前模块内；现在不建立该目录、不修改父POM。完成时交付 `README.md` 正文、后端 `pom.xml` / `src/`、完整 `frontend/` 和 `01-验证记录.md`。

从[第001课](21-04-001-hello-spring-security/README.md)完整前后端复制，保持JDK21、Boot4.0.8、Security7.0.7及现有前端基线。明确两个观察入口：后端保留 `GET /hello`，新增 `GET /public/info`；前端分别请求 `/api/hello` 与 `/api/public/info`，由Vite开发代理转发并去掉 `/api` 前缀。本课仍使用开发代理，不把结果称为已验证跨源认证。

正文围绕一个核心问题展开：**自行定义安全链后，哪些请求公开，哪些仍然必须认证，默认登录能力如何保留？**

1. 回顾第001课匿名401及HTML跳转，以已有行为作为对照。
2. 解释自动配置条件与自行定义 `SecurityFilterChain` 的关系；区分默认链退让和默认用户配置，避免笼统称为关闭自动配置。
3. 跟写公开接口、显式链及公开请求规则，配置 `formLogin` 和 `httpBasic`，其余请求仍要求认证。保留CSRF默认防护，写清每项配置的作用和不变的凭据交互。
4. 在前端增加公开说明按钮，沿用真实请求状态和错误恢复；按钮文字明确“公开信息”和“受保护接口”，不增加登录表单、角色管理或工单业务。
5. 对照公开与受保护请求，解释后端路径和浏览器代理路径、原始状态与页面提示，然后完成本课整体总结。

| 验证场景 | 预期证据 |
| --- | --- |
| 匿名GET公开接口 | 后端200；浏览器公开按钮展示真实响应 |
| 匿名访问受保护接口，Accept为JSON | 后端401；浏览器显示未认证及状态码 |
| 正确Basic访问受保护接口 | 后端200；证明认证能力仍工作 |
| 错误Basic访问受保护接口 | 后端401；无凭据泄露 |
| HTML导航到受保护接口 | 跳转登录入口；登录页仍可访问 |
| 公开路径的近似路径 | 不被过宽规则放行；按兜底认证规则处理 |
| 关闭后端再恢复 | 浏览器区分代理/网络故障与HTTP认证拒绝，恢复后可重试 |
| 回归第一课已有交互 | 原有匿名观察、键盘操作与窄屏布局仍可使用 |

第二课不提前讲完整登录/退出生命周期，不通过关闭CSRF简化后续课程，也不为展示403临时制造没有上下文的角色规则。第003课接认证错误契约，第005—009课逐步完成多用户、CSRF准备、页面登录、身份恢复和退出。
