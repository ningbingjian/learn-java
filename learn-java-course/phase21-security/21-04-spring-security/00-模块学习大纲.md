## 技术边界与主线

主线是 Servlet / Spring MVC 应用的身份认证、访问控制和请求防护。以 Spring Boot 组织工程，以 Spring Security 解释和实现安全行为，明确自动配置、框架执行机制和业务权限规则各自的职责。

工单系统随课程演进：访客访问公开说明，用户操作自己的工单，客服处理分配给自己的工单，管理员维护用户与权限。角色验证之后必须继续验证数据归属，不能把“登录成功”当成“可以操作任意工单”。源码系列围绕已经运行过的实例连续推进，覆盖配置构建和运行分支两条路径。

OAuth 2.0 / OIDC 的协议推导归21-03，本模块负责客户端和资源服务器的应用及实现；授权端点与签发服务归21-05；集中式身份平台归21-06；跨实例会话存储归21-07。上述能力在本模块出现时给出必要背景与整合边界。

## 第一篇：从接口进入安全模型

前提：Java、Maven、Spring Boot / MVC 与 HTTP 基础。

从未受保护的接口出发，观察依赖变化引起的认证要求、默认用户、登录页和 HTTP Basic 行为。区分认证与授权，认识请求安全链和业务 Controller 的执行边界，随后用显式 `SecurityFilterChain` 配置公开接口与需要认证的接口。说明 `requestMatchers` 与链匹配的职责，规则按什么顺序生效。

验收：能重现并解释200、401与登录跳转；能实现公开说明和受保护接口，验证放行范围，而不是只看到登录页就认为配置正确。

## 第二篇：身份认证与用户体系

前提：第一篇。从内存用户演进到数据库用户，学习用户详情、密码编码与校验、认证结果、失败处理、表单登录及退出。解释 `UserDetailsService` 的加载职责、`PasswordEncoder` 的校验职责，以及 `AuthenticationManager` / `AuthenticationProvider` 的协作；敏感凭据在何处产生、校验和清理。

实践逐步加入工单用户、登录页面和退出流程，再研究账号状态、密码升级、记住我与登录失败事件。多因素认证、一次性令牌和通行密钥作为后续扩展方向，按锁定版本确认具体 API 与运行依赖，不混入基础登录课。

验收：真实登录成功、错误密码、未知用户、禁用账户和退出后的访问都能被测试覆盖；能够区分用户加载失败与密码不匹配，日志不泄露密码。

## 第三篇：请求、方法与业务资源授权

前提：第二篇，方法授权前补齐 Spring AOP 代理基础。学习角色与权限标识、请求授权、方法授权、表达式和授权决策；解释 `AuthorizationManager` 的输入、决策结果及异常处理。

把工单角色规则进一步细化为资源归属：用户只能访问自己的工单，客服只能处理分配给自己的工单。研究方法调用绕过代理、路径规则遗漏、对象级越权及 ACL 的适用场景。区分前端菜单展示与后端授权。

验收：形成“主体 × 资源归属 × 操作”的权限矩阵，包含允许和拒绝两类证据；能解释规则看似存在却未执行的原因。

## 第四篇：安全上下文、会话与 Web 防护

前提：第二、三篇，并结合21-01的相关威胁模型。学习安全上下文的创建、保存、恢复和清理，会话固定攻击防护、并发会话、退出与请求缓存。引入 CSRF、CORS、安全响应头和请求防火墙，分别解释威胁来源、过滤阶段与配置边界。

比较浏览器自动携带 Cookie 与客户端显式发送 Bearer 凭据的条件；根据实际凭据传输方式决定 CSRF 策略，不用“前后端分离”或“用了 JWT”直接推断无需防护。Spring Session 的分布式存储实现交由21-07深入。

验收：能验证登录后的会话变化、缺失 CSRF 令牌的拒绝及正确令牌的通过，区分跨域预检失败与认证失败，并验证退出后的访问行为。

## 第五篇：核心架构与连续源码系列

前提：前四篇的可运行实例，使用与依赖完全匹配的源码标签。源码按问题连续展开，不以一次调用栈替代整体机制：

1. **启动与配置构建**：Boot 自动配置条件、`HttpSecurity`、配置器与共享对象，安全链怎样成为 Bean 并接入容器。
2. **请求入口与链选择**：`DelegatingFilterProxy`、`FilterChainProxy`、`SecurityFilterChain`，匹配规则与首条匹配链，过滤顺序及请求防火墙。
3. **上下文生命周期**：`SecurityContextHolder`、上下文仓库与相关过滤器；读取、显式保存、清理以及错误的跨线程使用。
4. **用户名密码认证**：Basic 和表单入口如何提取凭据，`ProviderManager` 怎样选择提供者，用户加载、密码校验、结果与失败处理如何协作。
5. **授权与异常转换**：`AuthorizationFilter`、授权管理器、`ExceptionTranslationFilter`、认证入口与拒绝处理器；对照匿名访问和已认证权限不足的分支。
6. **会话及退出链路**：会话策略、请求缓存、退出处理器与上下文清理，连接前四篇实际结果。

每一段都从业务现象进入具体类和方法，解释参数、状态与条件，提供断点或配置对照，再回到最初问题。记录被验证的具体路径以及未覆盖的替代实现。

验收：能独立定位一次认证或授权失败，说明启动时构造的配置如何影响运行时分支，并用日志、断点或测试证据支持解释。

## 第六篇：外部身份与令牌保护

前提：完成21-03的 OAuth 2.0 / OIDC 基础，再结合第五篇。学习 OAuth2 Login、OIDC 身份映射、OAuth2 Client 与授权客户端管理，资源服务器的 JWT 解码验证、不透明令牌内省、权限映射、多发行方边界和密钥轮换。

工单系统接入外部身份服务，并保护业务 API；客户端、资源服务器、授权服务器分别承担什么责任要始终明确。源码继续追踪相关认证过滤器、提供者、解码与权限转换。需要签发端时整合21-05或21-06的样例，不把自制 JWT 过滤器作为默认起点。

验收：除有效令牌外，验证过期、错误发行方、错误受众和权限不足；说明身份登录与访问令牌授权的区别。

## 第七篇：安全扩展、测试与生产诊断

前提：第五篇；协议场景依赖第六篇。实现有业务依据的认证提供者、授权管理器、身份映射和审计事件，解释扩展点的输入输出、调用位置和异常契约。研究多条链的顺序、重复过滤器注册、错误分派、安全上下文在线程切换中的传播，以及测试中模拟用户与真实认证的验证边界。

围绕登录循环、意外401/403、规则未匹配、跨域预检、会话丢失建立故障实验，按证据定位阶段、修复并重跑。性能分析关注密码散列成本、远程身份调用、令牌验证与授权查询，先建立负载和正确性基线，再比较变化；不凭单次请求推断吞吐能力。

验收：能给出故障复现、定位依据、修复及回归结果；性能改动有测量条件和安全语义保持的证据。

## 第八篇：综合交付与进阶边界

前提：前七篇。交付工单系统的身份与权限方案，形成威胁说明、权限矩阵、接口验证、审计与脱敏约定、配置管理、升级及回滚记录。根据应用形态比较会话、BFF和资源服务器方案。

具备阶段09的 Reactor / WebFlux 基础后，另开响应式安全实例，研究 `SecurityWebFilterChain`、响应式上下文和授权；不把 Servlet 的线程上下文结论直接搬过去。LDAP、SAML2、X.509及其他企业认证作为按场景选择的扩展分支，原生镜像与版本迁移按实际需求验证。

验收：主线系统能通过允许、拒绝和故障场景的整体验证，能解释技术选择与未覆盖范围；进阶分支单独声明准备条件与验证状态。
